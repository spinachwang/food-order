# product.md — 产品规格

> 本文件是规格的**单一事实来源（SSOT）**。CLAUDE.md 与代码不得在 spec 未更新前引入不一致的功能。架构转向记录见 [adr/0002-ai-agent-pivot.md](adr/0002-ai-agent-pivot.md)。

## 1. 一句话定位

`food-order` 是一个面向**办公室打工人**的**午餐决策助手** —— 通过多 Agent 协作，结合用户偏好、当前天气、附近餐厅，给出"今天吃啥 / 要不要点外卖 / 去哪家"的最终建议。

## 2. 目标用户

| 角色 | 描述 | 核心痛点 |
|---|---|---|
| 办公室打工人（"牛马"） | 每天中午 11:00–13:00 需要决定吃什么 | 决策疲劳、不知道附近有啥、担心踩雷、忌口常被忽略 |

> 不再覆盖原方案里的"商家 / 骑手 / 平台管理员"角色 —— 这些已废弃，详见 ADR 0002。

## 3. 核心场景（M1 Agent MVP）

1. **明确偏好**：用户说"今天想吃辣的" → 主 Agent 路由到川菜 + 湘菜专家 → 各出 ≥3 家餐厅 → 总结 Agent 输出建议。
2. **模糊意图**：用户说"随便推荐" → 主 Agent 根据用户偏好表 + 上次时间窗，挑 2–3 个候选菜系 → 并行出建议 → 总结 Agent 排序。
3. **天气驱动决策**：高温 / 沙尘 / 雨天 → 总结 Agent 倾向于点外卖；晴朗 + 适宜步行 → 倾向堂食 + 给出步行距离。

> **M1 不做反馈回写**：原场景 #4（采纳 / 否决 / 收藏 → 影响下次路由权重）延后到 M2。M1 用户通过修改 `cuisine_weights` / `allergies` 来表达偏好，反馈学习循环不在范围。

## 4. 非目标（明确不做）

- 不做实际外卖下单（仅推荐，不接美团 / 饿了么 API）
- 不做商家端后台 / 商家入驻
- 不做骑手调度
- 不做支付 / 会员 / 积分
- 不做小程序（仅 Web 聊天界面）
- 不做多租户 / SaaS

## 5. 系统形态

| 层 | 选型 | 说明 |
|---|---|---|
| 前端 | Vite + React 18 + TypeScript（**仅作聊天壳**） | 单页面：一个聊天窗口 + 流式输出 |
| 后端 | FastAPI + Python 3.11+ | 暴露 `/api/v1/agent/chat`（流式 SSE）+ 偏好 CRUD |
| Agent 编排 | **LangGraph** | StateGraph：主 Agent router → 菜系专家（并行） → 总结 Agent |
| 数据 | MySQL 8 + SQLModel | **仅一张核心表**：`user_preferences`（M1 不做 feedback → 不建 `user_feedback`）；用户标识用前端生成的匿名 UUID（M1 不做登录） |
| 外部服务 | **高德 MCP** | 餐厅周边搜索 + 当前/未来天气 |
